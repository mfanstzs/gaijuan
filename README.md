# DeskGrade

**Windows 本地运行的 AI 单题阅卷助手。**

DeskGrade 在应用内打开阅卷网站，按你手动框选的区域截取当前学生作答，结合标准答案和结构化评分点调用模型，再经过分数校验、填分读回和提交检查，辅助完成重复阅卷操作。

当前版本采用 **自备 API Key（BYOK）** 的本地模式：没有 DeskGrade 登录、注册、充值或次数套餐；模型调用由本机直接发给你配置的供应商，规则、记录和耗时日志保存在本机。默认模型配置使用千问，评分规则生成默认使用 `qwen3.8-max`。

> “本地版”不等于“离线模型”。学生答题截图及评分所需文本会发送到所选模型接口，供应商可能收费。仅在你有权使用的阅卷平台和答卷上运行，并对模型评分结果进行人工抽查。

## 能做什么

- **应用内网页**：使用 JavaFX WebView 打开阅卷网站，无需分别为 Chrome、360 等浏览器外壳配置操作。
- **按步骤配置模型**：主阅卷、备用阅卷、评分规则生成独立配置；完成后显示状态卡，编辑时才打开向导。
- **生成评分点**：填写学科、满分和标准答案，一键生成并保存结构化评分点，也可以手工编写。
- **手动框选与绑定**：每次运行自行标定答题区、分数框和提交按钮；支持提交后自动换卷、提交后另点下一题两种流程。
- **自动阅卷与安全停止**：按本轮数量停止，提供全局暂停/停止热键，保留防串分、分数读回和未知提交保护。
- **本地记录与耗时分析**：重启后读取历史评分与提交状态；逐份记录模型等待、截图、填分和提交等耗时。

## 开始使用

### 安装版

在本仓库的 [Releases](https://github.com/mfanstzs/gaijuan/releases) 中选择维护者发布的 Windows x64 安装包。若尚未发布安装包，可以按照下方源码运行方式构建。安装版包含 Java 运行时，不需要另装 Java、MySQL 或 Redis。

首次使用按以下顺序操作：

1. 在 **模型与 Key** 中配置千问主阅卷与规则生成用途，填写自己的 Key，完成能力验证，最后点击 **完成并收起**。备用模型可配置，也可停用。
2. 在顶部显示 **请在此打开评分网站** 的网址框输入阅卷网站地址，点击 **打开**，在应用内网页中进入待阅题目。
3. 在 **评分规则** 中填写学科、标准答案、满分和评分点并保存；也可一键生成后复核。
4. 在 **平台配置** 中选择当前内置网页，按实际提交方式框选全部必要区域，注册安全热键，点击 **完成本次框选并绑定**。
5. 在 **阅卷** 中填写本轮数量，查看开始条件，先用少量答卷测试，确认评分和页面操作正确后再扩大批次。

完整步骤、模型切换和常见问题见 [软件使用指南](docs/USER_GUIDE.md)。

### 从源码运行

需要 Windows x64、完整 JDK 21 和 PowerShell。仓库提供 Maven Wrapper，无需全局安装 Maven。首次构建需要联网下载依赖。

先获取源码，再将 JDK 路径替换为自己的安装位置：

```powershell
git clone https://github.com/mfanstzs/gaijuan.git
cd gaijuan
.\scripts\run-dev.ps1 -JavaHome 'C:\path\to\jdk-21'
```

该命令先构建和验证，再启动当前源码。不要同时运行多个构建进程；使用同一数据目录的 DeskGrade 也不能同时打开两个实例。

开发、IDEA 启动、测试和打包见 [本地开发指南](docs/DEVELOPMENT_LOCAL.md)。

## 工作方式与安全边界

```text
手动框选并绑定当前网页
  → 截取当前答题区
  → 本机请求模型
  → 校验结构化分项并由 Java 求和
  → 再核对答题区、填分、读回
  → 提交并观察结果
  → 下一份或安全停止
```

模型只返回评分建议，不直接控制鼠标键盘。只有通过应用校验的分数才可进入后续操作。等待评分期间换卷、窗口布局变化、分数读回不一致或提交状态不明确时，程序会停止；无法确定是否已经提交的答卷不会自动补交。

手动坐标方式观察到“页面推进”，不等于取得阅卷平台后台的保存回执。WebView 也不是任意网站兼容保证：依赖特殊浏览器插件、跨域登录流程或不支持的控件的网站，需要先验证是否可用。连续答卷画面相同等无法可靠区分身份的场景可能触发安全停止。

模型输出符合 JSON 格式不代表评分一定准确。请先用人工定标答卷检查评分点、部分分边界和识别效果，不要将软件当作免复核的最终裁决系统。

## 数据与隐私

默认数据目录为当前 Windows 用户的：

```text
%USERPROFILE%\.deskgrade\data
```

- `database/`：完整本地评分账本，包括学生转写、评分依据、规则快照和提交状态。
- `records/`：按日分段的评分与调用 JSONL 摘要。
- `performance/`：逐份耗时 JSONL 摘要。
- `settings/`：模型配置、用途选择及评分规则等设置。
- `credentials/`：当前 Windows 用户 DPAPI 加密的 Key 缓存。

安装包不应携带任何人的 Key、配置或学生记录。新答题截图仅在内存中用于请求，不作为新图片文件保存。**Key 加密不代表学生数据库也已加密**；备份或提交 Issue 前务必去除敏感内容。升级和备份前先退出应用，并备份整个数据目录，不要只保留 JSONL 摘要。

## 项目结构

| 目录 | 职责 |
| --- | --- |
| `grading-core` | 评分契约、规则校验、会话状态和安全边界 |
| `grading-adapters` | 模型接口、Windows 操作、本地存储和日志 |
| `grading-desktop` | JavaFX 界面、配置向导和内置网页 |
| `tools/mock-grading-site` | 本地合成阅卷测试工具 |
| `grading-gateway` | 保留的历史服务端模块；本地版运行不依赖它 |
| `scripts` | 构建、启动、打包与诊断脚本 |
| `prompts`、`contracts` | 评分提示词及结构化契约 |

原开发目录中保留部分历史云端架构文档；本地版操作以本 README 和上述两份指南为准。历史登录、次数和后台部署说明不属于当前安装版的必需步骤。

## 反馈与贡献

提交问题时请附上软件版本、Windows 环境、所用模型、可复现步骤和受限错误码。需要评分样例时，优先使用合成或充分匿名化的数据。不要提交 API Key、数据库、个人配置、原始学生答卷或真实平台登录信息。

修改后先运行默认测试；涉及截图、焦点、填分或提交的改动，还需要在受控 Windows 交互桌面验证。不要通过取消校验、对未知提交重发或失败时补零来让测试“通过”。

维护者准备首次公开仓库时，应使用安全源码导出脚本生成独立目录并复核，不要直接将包含历史运维资料的开发工作目录整体推送。流程见 [本地开发指南](docs/DEVELOPMENT_LOCAL.md)。
