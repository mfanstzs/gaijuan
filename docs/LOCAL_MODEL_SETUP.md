# 本地模型与 Key

打开“模型与 Key”后，先看三张用途卡：主阅卷、备用阅卷和评分规则生成。已配置且验证通过的用途只显示状态和模型名称，不再展开整页输入框；需要修改时才打开对应用途的编辑流程。

1. 选择要配置的用途和供应商。主阅卷、备用阅卷需要能看图的模型；评分规则生成只需要文本和结构化输出能力。备用不是必选项。新安装的三个用途默认提供千问模板，规则生成为 `qwen3.8-max`；模板本身不含 Key 或验证记录。
2. 按说明选择或填写模型，输入自己的 Key；已有缓存可以沿用，不回显。接口地址和结构化格式放在高级设置，普通用户不必反复填写。Key 只保存在 `%USERPROFILE%\.deskgrade\data\credentials` 的当前用户加密缓存，不随安装包导出。
3. 保存后进行对应能力验证。验证前会提示供应商可能收费；只有明确点击确认才发送合成图片或文本，不使用学生答案。已有相同配置、相同 Key 的有效验证可直接沿用。
4. 检查用途和验证结果，完成后才把它设为生效模型并收起编辑区。不要把“正在编辑”误认为“已经切换使用”。

仅打开编辑、切换步骤或取消，不会自动调用模型。第一步可直接选择“已有本机配置”；切换到千问等预设供应商时，优先选择该供应商完整接口地址精确匹配的已有配置。未改变配置且 Key、所需能力验证仍有效时，可沿用缓存并完成向导，不需要重复填 Key 或付费验证。

没有对应配置时才建立新草稿。更改接口、模型、参数或 Key 后仍需重新验证；不会把原供应商的 Key 悄悄发到新地址。取消会保留原生效用途；已经明确保存的草稿和已经发生的供应商调用不能被取消按钮撤销。升级只改变新安装默认值，不自动覆盖已经保存的用途选择；希望改为千问的旧用户可编辑“评分规则生成”并在最后一步确认启用。

Key 更换或忘记后，所有共用该 Key 的模型能力状态失效，需要分别重新验证。更改地址、模型或参数同样不能沿用旧验证。导入配置不等于导入 Key 或能力验证，不能把服务器验证结果冒充本机验证。

预置配置只是与项目现有模型相同的非秘密模板，并非免费服务或永久可用承诺。使用其他兼容接口时，在高级设置填写完整 Chat Completions 地址（以 `/chat/completions` 结尾）及该供应商可用的精确模型 ID；Key 会发送到这个地址，切勿使用来源不明的接口。模型能力、余额和供应商政策以实际账户为准；应用不再扣除或充值 DeskGrade 次数。

本地生成评分规则不再经过后台：填写学科、总分与标准答案后，本机请求已选文本模型，校验结构化评分点后供用户检查保存。模型返回非法结果、网络失败、记录无法写入时停止，不用默认分值继续。

Key 缓存只适用于当前 Windows 用户，不应随本地数据库、日志或安装包共享。需要更换电脑时填写自己的 Key；不要把源代码或 EXE 内置 Key 当作缓存。

## 千问 3.8 思考档位（0.2.4）

第二步新增思考档位选择，仅对已经核对的千问官方端点与支持型号开放，不把千问参数套用到 OpenAI、豆包或未知兼容服务。

| 选择 | 请求行为 | 注意事项 |
| --- | --- | --- |
| 保持当前配置 | 原有参数保持不变；空配置仍不传档位 | 升级、浏览和取消不会暗中切换档位或使原验证失效 |
| 非思考 | `enable_thinking=false`，不传力度 | 可以用固定规则短答题对照，仍需核对评分质量 |
| 低思考 | `enable_thinking=true`，`reasoning_effort=low` | 可能更快，但不保证与原档位评分完全相同 |
| 高思考 | `enable_thinking=true`，`reasoning_effort=xhigh` | 适合对照复杂判断；不作为升级后自动选项 |

当前官方文档说明 Qwen3.8-Flash 默认开启思考、默认力度为 `xhigh`；然而空参数使用的默认预算与显式指定 `xhigh` 的预算映射并不相同，所以“保持当前”不能直接替换成显式高档。客户端未传参数只能结合服务商文档推断默认行为，不能证明历史每次调用的思考耗时。见 [千问 Chat API 参数](https://help.aliyun.com/en/model-studio/qwen-api-via-openai-chat-completions) 与 [图像模型思考开关](https://help.aliyun.com/en/model-studio/vision)。

修改档位会生成独立待验证配置；重新验证并点击完成之前，原生效模型不变。不会改变评分点、结果校验、防串分或提交保护，但模型推理行为可能变化。建议用相同答卷/规则对照速度与分数，不能仅凭 API 成功或 JSON 合法认定评分质量等同。

## 豆包对比候选

供应商中增加火山方舟豆包，候选模型为 `doubao-seed-2-1-lite-260915`，使用官方北京 Chat API。它是额外候选，不在升级时替换现有主模型、备用模型或评分规则模型。当前官方列表列出该模型支持视觉理解和结构化输出，实际可用性仍须用自己的 Key 验证。[模型列表](https://docs.volcengine.com/docs/ark/model-list?lang=zh&redirect=1)

千问思考选择不适用于豆包。此次预设也不自动启用低延迟付费服务；方舟的 `service_tier=fast` 是另一个可选服务等级，不等于“低思考”，且能否获得低延迟取决于账户配额与服务情况。[方舟 Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=zh&redirect=1)
