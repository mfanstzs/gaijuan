# DeskGrade 本地版使用指南

本指南适用于当前 Windows 本地自备 Key 版本。软件无需登录 DeskGrade，也不需要自行部署后台或数据库。模型接口并非离线服务：你需要可用的供应商 API Key，使用费用由该 Key 所属账户承担。

建议先配置模型，再准备评分规则和网页绑定。首次使用只跑少量答卷，人工核对分数和提交行为。

## 1 配置模型与 Key

打开 **模型与 Key**，这里有三个独立用途：

| 用途 | 做什么 | 验证要求 |
| --- | --- | --- |
| 阅卷主模型 | 读取学生答题图片，按评分点评分 | 图像识别与结构化评分能力 |
| 备用阅卷模型 | 在符合回退条件时，对同一份输入再尝试一次 | 图像识别与结构化评分能力；可停用 |
| 评分规则生成 | 根据学科、标准答案和满分生成评分点 | 文本与结构化输出能力，不要求看图 |

新安装的默认模板均为千问：主阅卷 `qwen3.8-flash`，备用 `qwen3.8-max`，规则生成 `qwen3.8-max`。模板不是已配置的服务，也不包含 Key；模型是否开放、额度和网络可达性需要用自己的账户验证。升级后请以用途卡显示的实际生效模型为准，不能把新安装默认值当作已保存配置被替换的证明。

### 四步配置

1. **选择用途和供应商**：例如选择“评分规则生成”和“千问 / 阿里云”。本机已有同供应商配置时会优先选用，也可以直接在这一步的“已有本机配置”中选择。
2. **填写模型和 Key**：普通情况下保留模板接口，确认模型 ID 与供应商账户可用型号一致。已有配置的缓存 Key 和验证仍有效时可以沿用，否则填写自己的 Key，点击 **保存并继续**。接口地址和 JSON 输出模式放在高级设置中。
3. **验证能力**：按所选用途执行图像或文本验证。验证会发送合成测试内容，不使用学生答案；供应商可能收费，确认后才调用。相同配置已有有效验证时可以沿用。
4. **确认启用**：核对用途和模型后点击 **完成并收起**。返回状态卡，确认它显示了你希望使用的模型。

**保存草稿不等于启用模型。** 只选择供应商、切换下拉框或保存第二步，都不会改变当前用途；必须完成最后一步。取消向导会保留原生效用途，已经保存的草稿和已经发生的供应商费用不会被撤销。

### 切换规则生成模型

在“评分规则生成”卡片打开编辑流程，选择千问，按上述四步完成。请勿只修改主阅卷模型：三种用途互相独立，改变主模型不代表规则生成模型也变了。

切换供应商时不要沿用其他供应商的 Key。更改接口地址、模型、思考参数或 Key 可能使旧验证失效，需重新验证。输入框留空仅在界面明确提示可以沿用当前缓存时有效；“忘记此 Key”会同时撤销共用它的模型验证。

Key 将发送到配置的模型接口。不要使用来源不明的兼容地址，也不要把 Key 粘贴到 Issue、截图、代码或聊天记录中。

### 千问思考档位

已支持的千问接口与型号会显示以下选项：

- **保持当前设置 / 供应商默认**：不额外更改已保存参数。
- **不思考**：显式关闭支持型号的思考开关。
- **少思考**：使用低思考力度。
- **多思考**：使用较高思考力度。

修改档位后按向导保存、验证并确认启用。不同档位可能影响速度和分数，建议使用相同答卷与规则对照，而不是只看响应快慢。千问参数不会自动应用到豆包或其他兼容模型；不显示选项时，不代表该模型一定不支持思考，只表示应用未开放该组合的快捷设置。

## 2 打开评分网站

顶部网址框中的浅色文字 **请在此打开评分网站** 是输入提示，不是已经打开的网址。

输入目标阅卷网站地址并点击 **打开**。应用会打开独立的内置网页窗口；在该窗口中自行完成平台登录和题目选择。普通网站使用 HTTPS，本机合成测试仅允许 `http://127.0.0.1:8766/` 这一 HTTP 入口。

先调整网页窗口的尺寸和位置，让当前单题答案完整可见，再进行框选。内置网页采用 JavaFX WebView，不是完整 Chrome；遇到不支持的浏览器特性、跨域跳转或无法加载的页面时，不能仅靠重新框选解决。

打开网站不会自动赋予截图、填分或提交权限。当前流程只绑定应用内打开且成功加载的网页，不是对任意外部浏览器窗口进行操作。

## 3 准备标准答案与评分点

进入 **评分规则**，填写：

- **题号 / ID**：区分当前题目的名称或编号。
- **题目类型 / 学科**：例如“历史材料分析题”。
- **标准答案**：包含参考答案、等价表达和必要的给分说明。
- **满分与步长**：与平台实际允许的分数一致。
- **评分点**：逐项列明允许分值和给分边界。

可以自行填写评分点，再点击 **保存规则新版本**；也可以填写前述条件后点击 **AI 一键生成并保存评分点**。生成成功会保存新版本，开始阅卷前仍需人工复核。该操作调用已启用的规则生成模型，可能产生供应商费用，不是免费的本地模板填充。

评分点每行格式：

```text
评分点 ID | 允许分数（逗号分隔） | 评分要求
```

例如，一道满分 4 分、要求说明“适合防守而不宜进攻”的题目可以写为：

```text
P1 | 0,2 | 表达有利于防守、适合坚守或同等意思，得2分；遗漏或意思相反，得0分。
P2 | 0,2 | 表达不利于进攻、不宜强攻或同等意思，得2分；遗漏或意思相反，得0分。
```

这是合成示例，不是适合所有题目的通用规则。允许 `0,1,2` 时应写清 1 分与 2 分的边界；步长为 1 并不意味着每个评分点都必须允许 1 分。尽量明确“任选几个点”“意思相近可得分”“只有结论不给分”等要求，避免宽松说明与零分条件互相矛盾。

实际评分按标准答案、评分点和手动框选的学生作答判断，不要求额外填写题目原文。修改规则后须保存；进行中的旧评分不能继续获得填分权限。规则会保存在本机，重启后应恢复上次保存内容，未保存的输入不在此保证范围内。

## 4 框选并绑定当前网页

进入 **平台配置**，刷新并选择当前内置阅卷窗口。选择网站实际使用的提交方式：

| 提交方式 | 必需框选 |
| --- | --- |
| 提交后页面自动跳转 | 答题区域、分数输入框、提交按钮 |
| 提交后还需点击下一题 / 下一页 | 上述三处，再加提交成功提示区、下一题 / 下一页按钮 |

答题区只框当前题目的完整学生作答，不要包含分数框、提交按钮、计时器等会动态变化的控件。分数框和提交按钮分别框选，各区域不能重叠。手动下一题模式需要可稳定识别的提交成功提示；不能用一个随意区域代替。

完成标定后，点击 **完成本次框选并绑定**。单独点击“标定答题区域”只是记录一个位置，并未完成整个绑定。

在安全控制区域注册热键：

- `Ctrl+Alt+F8`：安全暂停。
- `Ctrl+Alt+F9`：立即停止。

热键不可用时禁止自动开始。当前框选仅用于本次运行，不保存成网站模板；重启、导航变化或窗口布局变化后需要重新框选。暂停、停止或配置变化会撤销当前操作权限，后续按界面提示重新绑定并主动开始，不会自动续跑。

## 5 开始与检查结果

返回 **阅卷**，填写 **本次阅卷数量**，范围为 `1–10000`。这表示本轮处理数量，不是软件收费额度。例如填写 5，达到本轮计数条件后停止；第三方页面自身自动换卷的行为不由该数量控制。

查看工具栏下方的开始条件。按钮灰色时，将鼠标移上去查看原因，并按提示处理；不要反复点击试图绕过检查。常见缺项有主模型未验证、备用未配置但仍启用、规则未保存、框选未绑定或热键注册失败。

启动后，程序按顺序截图、请求模型、校验评分、填分、读回、提交并观察页面变化。模型等待期间，答题区域显示上下扫描提示；这只是工作动画，不表示模型正在逐行识别，也不是评分准确性的证据。

自动运行会使用当前桌面的鼠标、键盘和焦点。期间不要滚动网页、缩放、拖动窗口或手动换卷；需要人工操作时先暂停。即便没有人工操作，网页自身动态内容也可能触发一致性保护。

### 提交结果未知怎么办

停止后先到阅卷平台人工核对该份是否保存，不要直接再次点击提交。记录中的“已填分”“已点击提交”“页面已推进”和“平台确认成功”不是同一种事实。

手动坐标模式主要观察局部画面和操作结果，页面推进并不等同于拿到平台后台保存回执。处理旧未决批次只结束自动流程，不会将未知结果改为成功，也不会替你补交。确认平台状态后，切到合适的下一份答卷，再重新绑定开始。

空白卷可以按规则评分为 0，但截取不完整、尚未加载、识别失败或无法判断不能当作空白卷强制补 0。重复画面也可能无法证明已经换人，因此触发停止不应直接取消防串分检查。

## 6 查看记录、耗时和备份

**记录** 页读取本机数据库。重启不会清空已保存历史；看不到记录时先点击查询、重置筛选，并核对是否使用同一个 Windows 用户和数据目录。

默认目录：

```text
%USERPROFILE%\.deskgrade\data
```

| 相对路径 | 内容 |
| --- | --- |
| `database/local-deskgrade.mv.db` | 完整评分和提交账本，记录页的数据来源 |
| `records/grading-*.jsonl` | 每行一个 JSON 的调用与评分摘要 |
| `performance/performance-*.jsonl` | 单份总耗时、模型等待、截图、填分、读回、提交等指标 |
| `logs/` | 有轮换期限和容量限制的运行故障日志 |
| `settings/` | 保存的规则、模型及用途选择 |
| `credentials/` | 当前 Windows 用户加密的 Key 缓存 |

完整记录与评分摘要不受运行故障日志轮换的影响。JSONL 摘要不能替代完整数据库；不要删除数据库后指望仅凭日志恢复全部学生转写和评分细节。

有源码的用户可在项目根目录汇总最近 20 份耗时：

```powershell
.\scripts\summarize-performance.ps1 -Last 20
```

模型等待包含网络、排队和供应商处理等环节，不等于单独的推理时间。截图细项属于嵌套指标，不能把所有计时字段直接相加；不同题目、不同空白数量和失败状态也会影响平均值。

备份前完全退出 DeskGrade，然后复制整个数据目录。升级安装保留用户数据，但仍建议先备份。DPAPI 缓存依赖原 Windows 用户，换电脑或分发给别人时应重新填写各自的 Key，不能把加密文件当作共享凭证。

学生转写和评分依据保存在本机数据库中，不等于已加密。分享日志或数据库前先脱敏；不要把数据目录提交到 GitHub。

## 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 选了千问，规则生成仍显示旧模型 | 是否编辑了“评分规则生成”用途，是否完成第四步并回到状态卡 |
| 生成评分点按钮灰色 | 查看悬停和页面提示；确认规则生成用途已启用、Key 有效，且学科、标准答案、满分等输入有效 |
| 已框选，但开始按钮灰色 | 是否标记所有必需位置并完成绑定；检查主/备模型、规则、热键与本轮数量 |
| 更换模型后要求重新验证 | 验证与接口、模型、参数及 Key 相关，旧验证不能直接沿用到不同配置 |
| 第一次验证就失败 | 核对供应商账户、模型 ID、额度、网络和能力要求；错误码不同，处理方式也不同 |
| 明明填了分却停止 | 查看是读回不一致、答题区变化还是提交未知；先核对平台，不能直接认定模型调用失败 |
| 阅卷速度慢 | 先看本地耗时日志；用同卷同规则对比模型/档位，避免为提速取消安全检查 |
| 重启后历史不见 | 确认本地初始化无错误、筛选已重置、用户和数据目录相同；保留原文件，不先删库重建 |
| 网站打不开或布局异常 | 确认网址和网络；JavaFX WebView 不保证兼容所有网站，不自动绕过安全页面或登录限制 |

提交反馈时，说明版本、模型、错误码和复现步骤即可；先使用合成答卷复现，避免公开真实学生内容和凭据。
